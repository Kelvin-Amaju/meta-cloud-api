# Netgrity Project Structure & Coding Conventions

Reference document describing the style, structure and programming principles of the
existing `app(1)` / `reyonhik` PHP applications. The goal is to make it possible to
start a new project quickly by reusing this exact structure and rule-set.

---

## 1. High-Level Overview

The application is a **procedural PHP 5/7 web application** (no framework) that uses:

- **mysqli** (single shared connection, `mysqli_select_db()` to switch schemas)
- **Sessions** for authentication (`MM_*` keys)
- **jQuery + AJAX** for almost all interactivity (form submit, list loading, CRUD)
- **Bootstrap admin template** ("Lucid" theme, `theme-orange`) with `select2`, `toastr`, `sweetalert`, `DataTables`
- **Composer** for a few libraries only (`phpoffice/phpspreadsheet`)
- Custom lightweight **XLSX writer** for exports (`SimpleXLSXWriterLite.php`)
- Custom **PDF/Dompdf** under `ajax/dompdf` for printable documents
- **Multiple logical MySQL databases** accessed through one connection, switched with `mysqli_select_db()`

The pattern is deliberately simple: **every file is a complete request handler**.
There is no router, no MVC, no ORM, no namespaces. Pages render HTML and talk to
small AJAX endpoints which contain the business logic.

### What belongs where

| Concern | Folder |
|---|---|
| Shared bootstrap / DB / helpers | `_includes/functions.inc.php`, `_includes/functions2.inc.php` |
| Domain helper functions | `_includes/<domain>_functions.inc.php` |
| Feature UI screens | `main/<feature>.php` |
| AJAX endpoints (create/update/approve/list) | `ajax/ajax_<feature>_<action>.php` |
| Report data assembly | `_includes/report_<x>_config/functions/builder.inc.php` |
| XLSX downloads | `ajax/export_<report>.php` |
| HTML fragments injected into pages | returned by ajax endpoints as raw HTML |
| Per-role navigation | `_menu/menu_<roleID>.inc.php` (generated by `build.php`) |

## 3. Core Bootstrap Files

### 3.1 `functions.inc.php` — the "front door" of every authenticated page

Every protected page starts like this:

```php
<?php require_once('../_includes/functions.inc.php');
require_once('../_includes/role_check.inc.php');
```

`functions.inc.php` does, **in order**:

1. `ob_start()`
2. `ini_set('display_errors', 0)`, `date_default_timezone_set('Africa/Lagos')`, `ini_set('max_execution_time', 900)`
3. Start session if not started (`if (!isset($_SESSION)) { session_start(); }`)
4. Define all DB name constants:
   `$db_main`, `$db_prod`, `$db_fleet`, `$db_facility`, `$db_outlet/$db_stock/$db_acc/$db_sales/$db_bk`, `$db_menu`, `$db_hr`
5. Connect once: `$dbsmart = mysqli_connect($hostname_dbsmart, $username_dbsmart, $password_dbsmart)`
6. Session timeout guard (redirects to `../index.php` when inactive)
7. Load the current user from `$_SESSION['MM_uID']` into `$user_fname`, `$user_lname`; redirects to `pwd/reset.php` if not found
8. Define global helper functions (see 4.1)
9. Set `$default_store`, `$mylocID = $_SESSION['MM_uRole']`

### 3.2 `functions2.inc.php` — lightweight version for public pages

Used only by `welcome.php` and login AJAX. Same DB + `GetSQLValueString` / `test_input` /
`fix_amt` / `get_ip_address`, **without** the user-session dependency.

### 3.3 `role_check.inc.php` — authorization gate

```php
$curPageName = substr($_SERVER["SCRIPT_NAME"], strrpos($_SERVER["SCRIPT_NAME"], "/") + 1);
// looks up menu_list where url = $curPageName
// then menu_build where roleID = $_SESSION['MM_uRole'] and menuID = ...
// redirects to check21.php / check22.php if not allowed
// sets $dispage2 = menu name (used in <title>)
```

This is why **every new protected page must be registered in the menu tables**
(`menu_list`, `menu_build`) — otherwise `role_check` redirects the user away.

### 3.4 Menu generation (`build.php`)

`build.php` regenerates `_menu/menu_<role>.inc.php` for every active role from the
`reyon_menu` database (`urole`, `menu_group`, `menu_list`, `menu_build`).

**Rule:** after adding a page to the menu tables, run `build.php` once. Never hand-edit `_menu/`.

## 4. Programming Style Conventions

### 4.1 Helper function patterns

- **Lookup helpers** — most repeated pattern in the codebase:

```php
function get_customer($x){
    if($x>0){
        mysqli_select_db($GLOBALS['dbsmart'], $GLOBALS['db_main2']);
        $query_sch = sprintf("SELECT name FROM `customers` WHERE custID=".$x);
        $count = mysqli_query($GLOBALS['dbsmart'], $query_sch) or die(mysqli_error($GLOBALS['dbsmart']));
        $row_count = mysqli_fetch_assoc($count);
        return $row_count['name'];
    }else{ return 'N/A'; }
}
```

  Convention: `get_<entity>($id)` → returns the display name or `'N/A'`.
  Always guard `$x > 0` first.

- **Input sanitising:** `test_input()` = trim + strip_tags + stripslashes + htmlspecialchars.
- **Money parsing:** `fix_amt()` = test_input then remove `,` / spaces / `N` / `E`, cast to float.
- **SQL building:** `GetSQLValueString($value, $type)` returns a properly escaped SQL literal
  (types: `text`, `int`, `long`, `double`, `date`, `defined`). Wrap queries in `sprintf`.

```php
$query = sprintf("SELECT * FROM users WHERE uID=%s",
    GetSQLValueString($_SESSION['MM_uID'], "int"));
```

- **Numbers → words:** `numberToWords()`, `convertToNairaWords()`, `AmountInWords()`.
- **Period helpers (reports):** `report_months_between()`, `report_quarter_label()`, `report_half_label()`, `report_valid_date()`.
- **Safe output (newer code):** `reyon_h($x)` / `report_html($x)` = `htmlspecialchars((string)$x, ENT_QUOTES, 'UTF-8')`.

### 4.2 File naming rules

| Type | Pattern | Example |
|---|---|---|
| UI page | `<entity>_<page>.php` | `customer_deposit.php`, `pending_requisition.php` |
| AJAX endpoint | `ajax_<entity>_<action>.php` | `ajax_create_customer.php`, `ajax_approve_prequest.php` |
| Shared include | `<domain>.inc.php` | `role_check.inc.php`, `report_functions.inc.php` |
| Sidebar include | `menu_<roleID>.inc.php` | `menu_1.inc.php` |
| Report config | `report_<x>_config.inc.php` | `report_e_config.inc.php` |
| Report data | `report_<x>_functions.inc.php` + `report_<x>_builder.inc.php` | `report_e_builder.inc.php` |
| XLSX export | `export_<report>.php` | `export_expense_schedule.php` |

All lowercase, `snake_case`, no spaces.

### 4.3 Session keys (`MM_` prefix)

| Key | Meaning |
|---|---|
| `$_SESSION['MM_uID']` | user id |
| `$_SESSION['MM_uRole']` | role id (also used as `$mylocID`) |
| `$_SESSION['MM_Username']` | alias of uID |
| `$_SESSION['MM_locID']` / `$_SESSION['locID']` | location |
| `$_SESSION['MM_lock']` | logged-in flag |

### 4.4 AJAX contract (IMPORTANT)

All AJAX endpoints return **plain text** (`dataType: "text"`). Two response styles:

1. **HTML fragment** — returned so the client can inject it into a div:
   ```js
   success: function (data) { $('#ram').html(data); }
   ```
2. **Status code** — `echo 1;` on success; on failure echo `0` or a human-readable error message.
   Client checks numerically:
   ```js
   success: function (data) {
       data = data.trim();
       if (data > 0) { toastr['success']('Saved'); }
       else { toastr['error'](data); }
   }
   ```

Endpoints must begin with `require_once('../_includes/functions.inc.php');` and guard the request:
```php
if (isset($_POST['x']) && $_SERVER["REQUEST_METHOD"] == "POST") { ... }
```

### 4.6 Database access conventions

- **One connection, many schemas.** Query on `$dbsmart`; switch schema with `mysqli_select_db($dbsmart, $db_xxx)` right before the query.
- **Cross-schema joins** use explicit `dbname`.`table`:
  ```sql
  LEFT JOIN `$db_main`.`customers` c ON c.custID = a.custID
  ```
- **Table names** are prefixed by domain (`stockitems`, `stockitems_fp`, `bincard_store`, `salesacc`, `dispatch_fp`, `customer_return_inv`).
- **Soft delete / status columns:** nearly every table has `status` (1 = active, 0 = disabled, and higher values encode workflow state, e.g. 24/26 for return approvals).
- Queries are built with `sprintf` + `GetSQLValueString`; never concatenate raw `$_POST`/`$_GET` into SQL.
- Legacy `md5()` + custom salt hashing is used for passwords in this codebase — new code should use `password_hash()`/`password_verify()`.

### 4.7 The Report Layer (the cleanest pattern in the codebase — reuse this)

Reports are split into four roles so they can be re-used by page, AJAX and export:

1. `report_config.inc.php` — company name, DB names (single source of truth).
2. `report_functions.inc.php` — formatting helpers (`report_money`, `report_month_label`, `report_period_from_request`, `reyon_h`, ...).
3. `report_<x>_config.inc.php` — table + column name mapping for one report (adjust once if live schema differs).
4. `report_<x>_functions.inc.php` / `report_<x>_builder.inc.php` — pure data assembly returning `array($products, $rows)`.
5. The page/AJAX/export file only **renders** or **writes** the result.

Example usage from `export_expense_schedule.php`:
```php
require_once('../_includes/functions.inc.php');
require_once('../_includes/report_functions.inc.php');
require_once('../_includes/SimpleXLSXWriterLite.php');

$period = report_period_from_request();          // parse + validate dates/months
$months = report_months_between($sdate, $edate); // build month/quarter/half columns
// ... assemble $rows ...
$xlsx = new SimpleXLSXWriterLite();
$xlsx->setSheetName('Expense Schedule');
$xlsx->setRows($rows);
$xlsx->setColWidths($colWidths);
$xlsx->output($filename);                        // streams the download
```

### 4.8 Backups

On the first login of each day, `welcome.php` creates `dbBackUp/YYYY-MM-DD/` and runs
phpMyBackupPro against a hard-coded list of databases (`$_POST['db']` array). New
projects should replicate this daily-backup behaviour but move the DB list into config.

## 5. Principles for Future Projects

The following rules capture the *intent* of the existing style so a new project can be
started without re-deciding everything.

### A. Architecture principles

1. **No framework, procedural PHP, one connection to MySQL via mysqli.** Keep the stack
   boring and transparent. Every file is a complete request handler.
2. **Separate the web root from shared code.** All shared PHP lives in `_includes/`;
   pages contain only presentation + wiring.
3. **One folder per concern** — exactly like section 2:
   `main/` (screens), `ajax/` (endpoints), `_includes/` (shared), `assets/` (static),
   `_menu/` (generated), `vendor/` (composer), `dbBackUp/` (daily snapshots).
4. **Keep config out of logic.** DB names, company name, table/column mappings live in
   dedicated `*_config.inc.php` files. A page should never hard-code a DB name.
5. **Never hand-edit generated files** (`_menu/*.inc.php`). Regenerate with `build.php`.
6. **Reuse helpers.** If a lookup (`get_customer`, `get_status`, ...) or a format
   (`fix_amt`, `convertToNairaWords`, `report_money`) already exists, use it. Add new
   generic helpers to `_includes/*_functions.inc.php`, never to a page.

### B. File & naming rules

7. Naming tables (from section 4.2):
   `main/<entity>_<page>.php`, `ajax/ajax_<entity>_<action>.php`,
   `_includes/<domain>.inc.php`, `_menu/menu_<roleID>.inc.php`,
   `_includes/report_<x>_config|functions|builder.inc.php`,
   `ajax/export_<report>.php`. Lowercase `snake_case`.
8. **One page file = one screen.** A page may call many AJAX endpoints, but an AJAX
   endpoint is never a page and a page never contains an endpoint.
9. Naming conventions inside code: session keys `MM_*`; lookup functions `get_<entity>`;
   page title var `$dispage`; table name prefixes by domain.

### C. Page lifecycle rules

10. Every protected page starts with exactly:
    ```php
    require_once('../_includes/functions.inc.php');
    require_once('../_includes/role_check.inc.php');
    ```
11. Every page uses the standard skeleton from 4.5 (`head_in.inc.php`, `nav.inc.php`,
    `side.inc.php`, `new_js_in.inc.php`, page script at the bottom).
12. **All writes go through AJAX.** Forms never do a synchronous POST to a page; they
    call `ajax/ajax_<entity>_<action>.php`, and the client shows `toastr` feedback.

### D. AJAX contract rules

13. Endpoint starts with `require_once('../_includes/functions.inc.php');`.
14. Guard: `if (isset($_POST['x']) && $_SERVER["REQUEST_METHOD"] == "POST")`.
15. Validate every input with `test_input()`; parse money with `fix_amt()`; escape into
    SQL with `GetSQLValueString()`; cast ids with `intval`.
16. Reply with either an **HTML fragment** (for injection) or **`echo 1;` on success /
    `echo 0` or error message on failure**. Client uses `data.trim(); if (data > 0)`.
17. Endpoints are unauthenticated-by-construction but protected by session checks inside
    `functions.inc.php` (user must be logged in) — keep it that way.

### E. Security principles

18. Never trust input: `test_input()` + escaping + int casting, always.
19. Escape output: use `reyon_h()` / `htmlspecialchars(..., ENT_QUOTES, 'UTF-8')` for any
    value echoed into HTML.
20. Never concatenate raw `$_POST`/`$_GET` into SQL. Prefer prepared statements or at
    minimum `GetSQLValueString`.
21. Passwords: use `password_hash()` / `password_verify()` in new code (do not copy the
    legacy md5 scheme).
22. Keep `display_errors` off in production; log to `error_log`. Do not ship `die(mysqli_error())` verbatim in new code.
23. Back up the databases daily into `dbBackUp/YYYY-MM-DD/` on first login of the day.

### F. Database principles

24. One shared `$dbsmart` connection; use `mysqli_select_db($dbsmart, $db_x)` to switch.
25. Define every schema name as a variable in `functions.inc.php`
    (`$db_main`, `$db_outlet`, `$db_menu`, ...). Never hard-code schema names in queries.
26. Cross-schema joins use `dbname`.`table`.
27. Every business table has a `status` column driving soft-delete and workflow states.
28. Use `sn`/`<entity>ID` as primary-key naming (`sn`, `uID`, `prodID`, `custID`, `refID`).

### G. Report rules

29. Build reports from the four-layer pattern (config → functions → builder → renderer)
    so the same data feeds HTML, AJAX fragments and XLSX exports unchanged.
30. Parse and validate all date inputs through `report_period_from_request()` /
    `report_valid_date()`; never trust raw date strings.
31. Exports stream through `SimpleXLSXWriterLite` (set sheet name → set rows → set column
    widths → output). Filenames: `report_<name>_YYYYMMDD_YYYYMMDD.xlsx`.

## 6. Starting a New Project — Step-by-Step Checklist

1. **Copy the scaffold:** `app/` containing `_includes/`, `main/`, `ajax/`, `assets/`,
   `_menu/`, `index.php`, `welcome.php`, `check.php`, `build.php`, `pwd/`.
2. **Rename config:** edit DB names, host, user, password in `_includes/functions.inc.php`
   and `_includes/functions2.inc.php`; set company name in `report_config.inc.php`.
3. **Create the databases** (main, outlet/menu, + any modules) with the conventions in 4.6.
4. **Set up auth:** `users`, `urole`, `menu_list`, `menu_group`, `menu_build` tables;
   implement `ajax_login.php` and `welcome.php` reusing `ajax_login.php` as the template.
5. **Build the menu:** run `build.php` so `_menu/menu_<role>.inc.php` files are generated.
6. **Add a feature** (repeat for each module):
   - create `main/<feature>.php` from the 4.5 skeleton;
   - register it in `menu_list`/`menu_build`;
   - create `ajax/ajax_<feature>_<action>.php` endpoints per the 4.4 contract;
   - wire client-side with jQuery + toastr;
   - run `build.php` again after menu changes.
7. **Add reports** via the four-layer pattern (4.7) and wire the export.
8. **Verify** each screen with a test user that has the role assigned in the menu tables.

## 7. Known Debt / Things to Improve in Future Projects

- Password hashing is legacy `md5` — use `password_hash()` in anything new.
- `display_errors` is disabled but `die(mysqli_error())` still leaks SQL on failure — replace with a shared error handler.
- CSS classes mix Bootstrap 3/4; pick one version per new project.
- Large inline `<script>` blocks on every page — consider extracting shared page JS into `assets/js/pages/`.
- `functions.inc.php` mixes connection config, session logic and 100+ helpers — keep it,
  but split new helpers into `_includes/<domain>_functions.inc.php`.
- The report layer already demonstrates the cleanest split (config/functions/builder) —
  use it as the model for new features, not just reports.
